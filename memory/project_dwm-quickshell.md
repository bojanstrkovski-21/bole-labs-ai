**chadwm-boki gap analysis:** already has the EWMH atoms Quickshell's state bridge needs. Missing the `isaltbar`/`managetray`-style patch (dwm-titus: `altbarclass = "quickshell"` in `dwm.c`) that reserves bar space for a `quickshell`-classed window instead of tiling it — chadwm-boki currently draws its own bar (`showbar`/`floatbar`) with a native XEmbed systray fed by `dwmblocks-async`. Recommended: port only the space-reservation patch + one `rules[]` entry, skip porting dwm-titus's `tomlparser.c`/hot-reload-TOML system (chadwm-boki's static config.h+rules[] approach is fine as-is), bind new keys straight to `quickshell ipc --path ... call <target> <function>`.

**showbar/showsystray**: both are pure runtime guards throughout `dwm.c` (`updatesystray()` itself starts with `if (!showsystray) return;` at `dwm.c:3747`; `showbar`/`m->showbar` gates `drawbar()` and the bar-space geometry math in `arrangemon()`). Setting both to `0` in config.h is sufficient and safe — no surrounding code needs deleting/commenting, keeps the diff against upstream minimal. Loose ends once that's done: the `togglebar` keybind (`MODKEY+b`) would still flip the old bar back on if pressed; `dwmblocks-async`/`STATUSBAR "dwmblocks"` references in keybinds become dead-but-harmless.
